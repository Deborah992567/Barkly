preparation is reproducible via
[`ml/scripts/prepare_real_datasets.py`](../scripts/prepare_real_datasets.py);

### 1.2 Label taxonomy

`train_label.csv` contains `audio_id`, `environement` (sic — environment), and
`activity`. Raw label strings were normalized case and whitespace
(`_normalize_label`), so variants like `Rest`/`rest` collapse to a single
canonical label.

| Canonical label | Count | Share |
|-----------------|-------|-------|
| seeking_attention | 1,818 | 14.6% |
| playing_with_human | 1,797 | 14.4% |
| playing_with_toy | 1,779 | 14.3% |
| playing_with_other_animals | 1,774 | 14.2% |
| rest | 1,770 | 14.2% |
| alerting_to_sounds | 1,754 | 14.1% |
| taking_shower | 1,245 | 10.0% |
| begging_for_food | 541 | 4.3% |

### 1.3 Environment metadata

Each sample carries an environment context (e.g. `indoor (general)`,
`near door`, `on grass`) stored in `SampleManifest.metadata.environment`. The
environment column is kept as context; it is not used as a training label.

### 1.4 Splits (leakage-safe)

Random split, seed 42, exact-duplicate hashes removed before splitting.
Cross-split leakage check (hash, id, dog) reports **no leakage**.

| Split | Samples |
|-------|---------|
| Train | 8,734 |
| Val | 1,871 |
| Test | 1,873 |

### 1.5 Known limitations

- Activity labels describe **behavioral context**, not vocalization type.
- Labels were generated by a vision-language model then manually verified;
  systematic VLM bias cannot be ruled out.
- No dog identity or breed metadata → per-dog generalization cannot be
  verified, and a per-dog (identity) split is not possible.
- Sourced from online videos: variable recording quality and background noise.

## 2. DogPoseCV (vision)

### 2.1 Summary

| Field | Value |
|-------|-------|
| Dataset ID | `dogpose-cv` |
| Modality | Image (JPEG) |
| Raw images | 20,730 (20,580 breed folders + 150 unlabeled `validation/` files) |
| Labeled (CSV) | 20,423 unique IDs; 20,562 file matches incl. duplicate-name copies |
| Removed: unlabeled | 168 |
| Removed: exact duplicates | 365 sample instances (226 groups) |
| After dedup | 20,197 |
| Classes | 4 pose labels |
| License | Apache-2.0 |
| Source | Stock & Cavey (Colorado State); arXiv:2101.02380 |
| URL | https://huggingface.co/datasets/stockeh/dog-pose-cv |
| Dog identity | Not provided |
| Breeds | README claims 120; 119 per-breed label CSVs found (breed kept as metadata) |

### 2.2 Label taxonomy

Labels come from one CSV per breed folder (`labels/*.csv`, columns `id,label`).

| Canonical label | Count | Share |
|-----------------|-------|-------|
| standing | 6,983 | 34.6% |
| undefined | 6,190 | 30.6% |
| lying | 4,055 | 20.1% |
| sitting | 2,969 | 14.7% |

### 2.3 Splits (leakage-safe)

Random split, seed 42, exact-duplicate image hashes removed before splitting.
No known dog-identity grouping exists, so images are treated as independent
instances (`dog_id == sample_id`). Cross-split leakage check (hash/id) reports
**no leakage**.

| Split | Samples |
|-------|---------|
| Train | 14,137 |
| Val | 3,029 |
| Test | 3,031 |

### 2.4 Known limitations

- Pose (standing/sitting/lying) is an observable physical signal, **not** a
  behavioral state; a standing dog may be relaxed, alert, playful, or afraid.
- The large `undefined` class (~31%) reflects label difficulty and low visual
  information; it contributes limited behavioral signal and increases
  baseline difficulty.
- Web-scraped, curated: inconsistent lighting, angles, and backgrounds.
- No temporal information (static images).
- The shipped `validation/` folder (150 files) is unlabeled; the pipeline
  drops it and its byte-identical copies of labeled images. Verification
  details: see `dataset-validation-report.md`.

> **Verified vs advertised:** the README claims 20,578 images with
> standing/sitting/lying/undefined = 4,143/3,038/7,090/6,307. The shipped
> label CSVs yield standing 7,047 / undefined 6,258 / lying 4,110 /
> sitting 3,008 (20,423 unique IDs). The CSVs are the source of truth.

## 3. Behavior of the prepared manifests

- Processed manifests (`train.yaml`, `val.yaml`, `test.yaml`, `manifest.yaml`)
  are written under `ml/data/processed/{dataset}/` (git-ignored; datasets of
  this size are not version-controlled).
- `manifest.yaml` concatenates the splits and records the `split` field per
  sample, so a single file drives training, evaluation, and inference tests.
- File hashes are stored per sample to make cross-split leakage checks
  deterministic and auditable.
