# BARKLY API Contract

The BARKLY backend exposes a versioned REST API. All application routes live
under `/api/v1`. Health probes live at the root (`/health`, `/ready`) and are
unversioned.

Interactive documentation is generated by FastAPI:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- OpenAPI JSON: `http://localhost:8000/openapi.json`

## 1. Transport

- JSON request/response bodies (UTF-8).
- Bearer token authentication (`Authorization: Bearer <token>`).
- Synthetic request identifiers: the middleware accepts an inbound
  `X-Request-Id` (any UUID) and echoes it on every response; otherwise a value
  is generated. A `X-Correlation-Id` may also be supplied and is propagated to
  logs.
- Media upload uses `multipart/form-data` (a `media_type` form field plus a
  `file` part).

## 2. Error envelope

Every error response uses a single envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "human readable explanation",
    "request_id": "2f8b1c4e-…",
    "details": null
  }
}
```

`details` is `null` normally and a list of per-field validation entries for
`422 VALIDATION_ERROR` responses.

### Error codes

| Code | HTTP | Meaning |
| --- | --- | --- |
| `VALIDATION_ERROR` | 422 | Request body/query failed schema validation |
| `UNAUTHENTICATED` | 401 | Missing, malformed, or expired token |
| `INVALID_CREDENTIALS` | 401 | Wrong email/password on login |
| `EMAIL_TAKEN` | 409 | Unique email already registered |
| `DOG_NOT_FOUND` | 404 | Dog id does not exist or is not owned by the caller |
| `ANALYSIS_NOT_FOUND` | 404 | Analysis id does not exist or is not owned by the caller |
| `RESOURCE_NOT_FOUND` | 404 | Generic owned-resource lookup miss (media id) |
| `NOT_FOUND` | 404 | Route does not exist |
| `MEDIA_INVALID` | 422 | Unsupported content type / extension / media type mismatch |
| `MEDIA_TOO_LARGE` | 413 | Upload exceeds `MAX_UPLOAD_SIZE_BYTES` |
| `DOG_HAS_ANALYSES` | 409 | Delete denied because the dog has historical analyses |
| `ANALYSIS_NOT_COMPLETED` | 409 | Feedback only valid on `COMPLETED` analyses |
| `PROVIDER_ERROR` | 500 | Inference provider failed for an internal reason |
| `INTERNAL_ERROR` | 500 | Unhandled error |

## 3. Endpoints

### Health

| Method | Path | Description |
| --- | --- | --- |
| GET | `/health` | Liveness. Returns `{"status":"ok","service":"barkly-api","request_id":…}` |
| GET | `/ready` | Readiness (checks DB connectivity). `200` when ready, `503` otherwise |

### Auth

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/auth/register` | Create account → `201` `TokenResponse` |
| POST | `/api/v1/auth/login` | Email+password → `200` `TokenResponse` |
| GET | `/api/v1/auth/me` | Current user profile (requires token) |

`TokenResponse`:

```json
{
  "token_type": "bearer",
  "access_token": "<jwt>",
  "expires_in": 1800,
  "user": { "id": "…", "email": "…", "display_name": "…", "created_at": "…" }
}
```

Access tokens are short-lived (default 30 minutes, `HS256`). Passwords are
hashed with bcrypt (12 rounds).

### Dogs

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/dogs` | Create dog → `201` |
| GET | `/api/v1/dogs` | List owned dogs |
| GET | `/api/v1/dogs/{dog_id}` | Fetch one owned dog |
| PATCH | `/api/v1/dogs/{dog_id}` | Partial update (at least one field) |
| DELETE | `/api/v1/dogs/{dog_id}` | Delete (→ `409` if the dog has analyses) |

A dog body is `{name, breed?, sex?, date_of_birth?, notes?}`.

### Media

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/media/upload` | `multipart/form-data` upload → `201` `MediaAssetRead` |
| GET | `/api/v1/media/{media_id}` | Metadata for an owned asset |

Uploaded content is validated (content type, extension, size), persisted via
the storage abstraction, and described by an opaque `media_id`.
**Internal storage references are never returned.**

### Analyses

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/analyses` | Create a behavioral analysis → `201` (may replay on same `idempotency_key`) |
| GET | `/api/v1/analyses/{analysis_id}` | Fetch one owned analysis |

Analysis creation payload (`AnalysisCreateRequest`):

```json
{
  "dog_id": "<uuid>",
  "input_type": "AUDIO | VIDEO | IMAGE | BEHAVIOR",
  "media_ids": ["<uuid>", "…"],
  "sound_category": "BARK | WHINE | WHIMPER | GROWL | HOWL | SIGH | UNKNOWN",
  "duration_ms": 2500,
  "context": {
    "owner_presence": "HOME | AWAY | UNKNOWN",
    "activity_state": "RESTING | WALKING | PLAYING | EATING | UNKNOWN",
    "time_of_day": "MORNING | AFTERNOON | EVENING | NIGHT | UNKNOWN",
    "recent_feeding": true, "recent_walk": true, "recent_play": true,
    "presence_of_strangers": false, "presence_of_other_animals": false,
    "recent_stressful_event": false,
    "location_category": "…", "notes": "…"
  },
  "idempotency_key": "optional-client-chosen-string"
}
```

Validation rules:

- `AUDIO` / `VIDEO` **require** ≥ 1 `media_ids` entry, and all referenced media
  must be owned by the caller and untethered to another analysis.
- `BEHAVIOR` must have an **empty** `media_ids` list.
- `sound_category` only applies to `AUDIO`; `duration_ms` only to
  `AUDIO` / `VIDEO`.

### History

| Method | Path | Description |
| --- | --- | --- |
| GET | `/api/v1/history` | Paginated, filtered history of the caller's analyses |

Query parameters: `page` (≥1), `page_size` (1–100, default 20),
`dog_id`, `behavior`, `date_from`, `date_to`, `status`.

Response (`HistoryResponse`):

```json
{
  "items": [ "…" ],
  "page": 1,
  "page_size": 20,
  "total": 1,
  "has_next": false
}
```

Ordering is newest-first (`created_at DESC, id DESC`).

### Feedback

| Method | Path | Description |
| --- | --- | --- |
| POST | `/api/v1/analyses/{analysis_id}/feedback` | Confirm or correct an analysis |

Body: `{"verdict": "CONFIRMED"}` or
`{"verdict": "CORRECTED", "corrected_behavior": "ALERT", "comment": "…"}`.

- `CORRECTED` requires `corrected_behavior`.
- Only `COMPLETED` analyses accept feedback (`409` otherwise).
- The originally predicted behavior is snapshotted on the feedback record so
  corrections remain auditable even if models change later.

## 4. Analysis response shape

`AnalysesRead` (create + fetch) includes:

```json
{
  "analysis_id": "<uuid>",
  "dog_id": "<uuid>",
  "status": "COMPLETED",
  "input_type": "AUDIO",
  "media": [{ "media_id": "…", "media_type": "AUDIO", "media_metadata": null }],
  "context": { "…": "…" },
  "failure": null,
  "result": null,
  "created_at": "…",
  "started_at": "…",
  "completed_at": "…",
  "version": 1
}
```

`status` is always present: `CREATED → QUEUED → PROCESSING → COMPLETED | FAILED`.

`result` (when `COMPLETED`): `AnalysisResultRead`

```json
{
  "primary_behavior": "ATTENTION_SEEKING",
  "confidence": 0.76,
  "secondary_behaviors": ["UNKNOWN"],
  "detected_audio_category": "BARK",
  "observations": [
    { "category": "AUDIO", "description": "…" }
  ],
  "explanation": "The observed pattern appears consistent with attachment-seeking behavior…",
  "disclaimer": "BARKLY provides AI-based behavioral estimates… not veterinary diagnoses.",
  "provider": "development-placeholder",
  "model_name": "barkly-placeholder",
  "model_version": "0.0.0-development",
  "is_placeholder": true,
  "generated_at": "…"
}
```

`failure` (when `FAILED`): `{ "code": "PROVIDER_UNAVAILABLE | …", "message": "…" }`.
`result` is `null` on failure.

## 5. Enum values (backend)

Stored as strings. Behavior taxonomy is designed to evolve without migration
churn (new values append; old values stay valid).

- `BehaviorState`: `RELAXED, ALERT, PLAYFUL, EXCITED, CURIOUS, ATTENTION_SEEKING, FEARFUL, STRESSED, AGGRESSIVE, SUBMISSIVE, RESTLESS, UNKNOWN`
- `AudioCategory`: `BARK, WHINE, WHIMPER, GROWL, HOWL, SIGH, UNKNOWN`
- `AnalysisStatus`: `CREATED, QUEUED, PROCESSING, COMPLETED, FAILED, CANCELLED`
- `MediaType` / `AnalysisInputType`: `AUDIO, VIDEO, IMAGE` (+ `BEHAVIOR` input)
- `FeedbackVerdict`: `CONFIRMED, CORRECTED`
- `FailureCode`: `PROVIDER_UNREACHABLE, PROVIDER_TIMEOUT, PROVIDER_UNAVAILABLE, PROVIDER_ERROR, INVALID_PROVIDER_RESPONSE`
- `OwnerPresence`: `HOME, AWAY, UNKNOWN` · `ActivityState`: `RESTING, WALKING, PLAYING, EATING, UNKNOWN` · `TimeOfDayCategory`: `MORNING, AFTERNOON, EVENING, NIGHT, UNKNOWN`

## 6. Idempotency

`POST /api/v1/analyses` accepts an optional client-chosen `idempotency_key`.
Replaying the same key **for the same user** returns the identical analysis
(server-side lookup), so retries after network failure do not create duplicate
records. Keys are opaque strings (max 128 chars) and are scoped per user.

Client guidance: generate a stable UUID/string per logical "session" once the
analyses request is about to be sent, and reuse it on retries. Do not reuse the
same key across unrelated analyses.

## 7. Swift (Phase 1) ↔ API mapping

Phase 1's `Barkly` app talks to in-memory mocks. The backend is the future
replacement transport. Enum values are translated at the API boundary; the
backend canonical form is the uppercase codes above.

| Swift (Phase 1) | Backend |
| --- | --- |
| `BehaviorState.calm` | `RELAXED` |
| `BehaviorState.playful` | `PLAYFUL` |
| `BehaviorState.excited` | `EXCITED` |
| `BehaviorState.alert` | `ALERT` |
| `BehaviorState.curious` | `CURIOUS` |
| `BehaviorState.anxious` | `STRESSED` |
| `BehaviorState.fearful` | `FEARFUL` |
| `BehaviorState.attentionSeeking` | `ATTENTION_SEEKING` |
| `BehaviorState.potentiallyThreatening` | `AGGRESSIVE` |
| `BehaviorState.unknown` | `UNKNOWN` |
| `AnalysisInputType.audio` | `AUDIO` (media_ids required) |
| `AnalysisInputType.video` | `VIDEO` (media_ids required) |
| `AnalysisInputType.photo` | `IMAGE` (media_ids required) |
| `AnalysisInputType.behavior` | `BEHAVIOR` (no media) |
| `VocalizationType.bark…silence` | `AudioCategory` (bark→`BARK`, etc.; silence→`UNKNOWN`) |
| Protocol `AnalysisRepository.requestAnalysis(for:inputType:vocalizationType:duration:)` | `POST /api/v1/analyses` |
| Protocol `DogRepository.fetchDogs()/fetchDog(id:)/updateDog(_:)` | `GET/PATCH /api/v1/dogs` |
| Protocol `HistoryRepository` | `GET /api/v1/history` |
| Protocol `InsightsRepository` | Future Phase 3 (derived statistics) |

Replacing the mocks is intentionally deferred to a later phase; this document
is the compatibility reference so that work is mechanical, not interpretive.
